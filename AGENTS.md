# AGENTS.md — ASTRA: ZERO HOUR

A two-page Next.js event/marketing site — no backend, API, or data layer. Keep changes scoped to that reality.

## Commands (from package.json)
- Node.js 20+. `npm install` → `npm run dev` (http://localhost:3000); production is `npm run build` then `npm start`.
- `npm run typecheck` (`tsc --noEmit`) is the **only** static verifier. There is no lint script, no test suite, and no CI — don't invent `npm test` / `npm run lint`.
- `postcss` is pinned via the `overrides` field in package.json. Leave it; removing it can reintroduce the upstream vulnerability it patches.

## Env & content gates
- Copy `.env.example` to `.env.local`. Two public vars, both read only in `lib/event.ts`:
  - `NEXT_PUBLIC_SITE_URL` — falls back to a vercel.app placeholder. It drives canonical URLs, sitemap, robots.txt, Event JSON-LD, and OG/Twitter tags via `metadataBase`; changing it changes all of these at once.
  - `NEXT_PUBLIC_GOOGLE_FORM_URL` — empty by default; `/register` shows a disabled "coming soon" button until it is set. The site itself never collects participant data.
- Structural event data (dates, tagline, rounds, timeline, nav sections, registration fields) lives in `lib/event.ts` as `as const` literals — change it there, don't duplicate JSX. Some marketing copy and "03 December 2026" strings are still hard-coded in `app/page.tsx` / `app/register/page.tsx`; keep those in sync with `event.dateLabel` / `event.startDate`.

## Date & animation quirks
- Countdown target `event.dateTime` = `2026-12-03T00:00:00+05:30` (IST midnight) is a placeholder because the real start time is unconfirmed. It's a client component and flips to "MISSION DAY IS HERE" once the target passes.
- `components/mission-motion.tsx` (client, GSAP + ScrollTrigger) is what animates `[data-reveal]` elements and `.section-backdrop` images; both pages mount it. New sections need those hooks to be animated, and the effect bails out entirely under `prefers-reduced-motion: reduce`.

## Public-content constraints (from README — do not "helpfully" add these)
- Only two public operations: **Operation: Black Box** and **Operation: Compromised Node**. Never publish the hidden twist details or internal organising-team duties.
- The compromised station must stay unmarked. `components/network-visual.tsx` deliberately draws a neutral 8-node graph; the source PDF diagram highlights a station — do not port that into the site.
- Venue, start times, other guest speakers, sponsors, and contact details are intentional placeholders. The **Chief Guest** is real content: edit the `chiefGuest` object in `lib/event.ts` (name, designation, bio, stats, service record) and replace `public/images/chief-guest.webp` to change the photo. After deployment the production sitemap must be submitted in Google Search Console.

## Small gotchas
- TS alias `@/*` → repo root (e.g. `@/lib/event`) in tsconfig.json. `next-env.d.ts` is generated by Next — don't edit it.
- Backdrop image paths in `app/page.tsx` are URL-encoded (e.g. `Screenshot%202026-11-13%20185056.png`) although the files in `public/images/` have literal spaces. Match the encoded form for new ones.
- `work/` holds local server logs (scratch), not source. `.next/`, `.npm-cache/`, `*.tsbuildinfo`, and `.env*` are generated/ignored; only `.env.example` is tracked.
